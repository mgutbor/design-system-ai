# ADR-001: Monorepo con pnpm + Turborepo

- **Estado**: Aceptado (F0)
- **Fecha**: 2026-08

## Contexto

El proyecto necesita múltiples paquetes que evolucionan juntos: tokens, componentes React, capa de IA y aplicaciones (docs, playground, api). Cambios atómicos entre paquetes, tipos compartidos y un único CI son requisitos.

## Decisión

Monorepo gestionado con **pnpm workspaces** (`apps/*`, `packages/*`) y **Turborepo** para el pipeline de tareas (build, typecheck, lint, test, validate) con caching.

## Alternativas consideradas

- **Nx**: más potente, pero demasiado opinado y pesado para esta escala (5 paquetes).
- **Scripts pnpm puros**: funcionan, pero sin caching ni pipeline declarado.
- **Repos separados (multi-repo)**: más coste de sincronización para un solo mantenedor.

## Consecuencias

- Cache de tareas: cambios en un paquete no re-ejecutan tareas ajenas.
- `packageManager: pnpm@10` fijado en el root `package.json` para reproducibilidad.
- Límite autoimpuesto (SPEC §12): no añadir un 6º paquete sin revisión.
