# ADR-002: React para componentes, docs app y playground

- **Estado**: Aceptado (SPEC v3)
- **Fecha**: 2026-08

## Contexto

El DS debe ser mantenible por una sola persona a largo plazo, con Storybook, testing a11y, theming por tokens y un AI Assistant. El autor domina React y Angular. Se consideró la portabilidad cross-framework (Web Components).

## Decisión

**React + TypeScript** para los componentes del DS y para las aplicaciones (docs, playground). La capa de tokens es **framework-agnóstica** (CSS custom properties + JSON).

## Alternativas consideradas

| Criterio                 | React             | Angular                    | Web Components          |
| ------------------------ | ----------------- | -------------------------- | ----------------------- |
| DX + Storybook + Vite    | Excelente         | Fricción histórica         | Verboso                 |
| Testing (Vitest + RTL)   | Nativo            | TestBed extra              | Frágil (shadow DOM)     |
| a11y                     | Ecosistema maduro | Bueno, menos estándar      | Cuidados extra          |
| Theming con CSS vars     | Directo           | View encapsulation estorba | Funciona con disciplina |
| Versionado               | Churn bajo        | Majors agresivas           | Fragmentación           |
| Mantenimiento individual | Bajo              | Medio                      | Alto                    |
| Interoperabilidad        | Solo React        | Solo Angular               | Universal               |

## React 19: ref como prop (ref-as-prop)

Los componentes del DS exponen `ref` mediante el mecanismo **ref-as-prop** de React 19, no mediante `forwardRef`.

- **Decisión**: los tipos usan `ComponentPropsWithRef<'button' | 'input'>` y el componente desestructura `ref` como una prop ordinaria, pasándola al elemento nativo.
- **Motivo**: `forwardRef` está deprecado en React 19; pasar `ref` como prop normal es el mecanismo recomendado, elimina el wrapper y simplifica la implementación sin coste alguno.
- **API pública**: sin cambio. El consumidor usa `<Button ref={ref}>` / `<Input ref={ref}>` exactamente igual que con `forwardRef`; el tipado (`ComponentPropsWithRef`) garantiza el mismo contrato.
- **Consecuencia**: si en el futuro se necesitara soportar React <19, la migración a `forwardRef` sería mecánica y local, sin impacto en la API pública.

## Consecuencias

- El DS no se puede consumir desde Angular sin un wrapper.
- Si surge demanda Angular real, se añadirá un wrapper layer (componentes React envueltos como Web Components) — no se reescribe nada; la API es pequeña y los tokens ya son agnósticos.
- La decisión es revisit-able y se documenta esta ruta como evolución futura.
