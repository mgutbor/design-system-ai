# ADR-003: Design Tokens en capas con regla estricta de minimización

- **Estado**: Aceptado (F0)
- **Fecha**: 2026-08

## Contexto

Se necesita una arquitectura de tokens explícita y framework-agnóstica que evite tanto tokens excesivamente genéricos como excesivamente específicos.

## Decisión

Cuatro capas en JSON como fuente única: **Primitive → Semantic → Component → Theme**, con generación de CSS custom properties y TypeScript tipado.

Reglas duras:

1. **Un component token solo se crea si aporta semántica que los tokens semánticos no expresan.** Si resuelve 1:1 a un semántico (p. ej. `button.primary.background` → `color.action.primary`), no se crea: el componente usa el semántico directamente.
2. Un semántico nace cuando **2+ componentes** comparten el mismo concepto.
3. Los themes sobreescriben **solo tokens semánticos**, nunca primitivos.
4. El validador emite warnings de _unreferenced semantic tokens_ y _alias-only component tokens_ para eliminar deuda.

## Alternativas consideradas

- **Tokens planos (sin capas)**: simples pero sin semántica reutilizable ni theming limpio.
- **Style Dictionary / Tokens Studio**: potentes pero añaden dependencias y un DSL ajeno; el generador propio es ~150 líneas y se entiende al 100%.
- **CSS Modules solo**: sin capa compartida ni validación.

## Consecuencias

- F0 produce 0 component tokens (regla 1).
- El validador garantiza contraste WCAG 2.2 AA por construcción (`contrast.json`).
- El generador es código del propio repo (educable y auditable).

## Auditoría de uso (dead-token audit)

La fuente de verdad del uso de tokens es **el código real**, no una lista manual ni metadata duplicada: el validador, en modo `scanCode` (activado por el CLI y CI), escanea `var(--…)` en los fuentes del repo (`packages/*/src`, `apps/*/src`, `.storybook`) y marca como referenciados los tokens encontrados (`collectCssVarNames`). Un `var(--…)` que no corresponde a ningún token genera un warning (detección de typos). Un token semántico solo se reporta como _unreferenced_ si no lo referencia ni el JSON, ni `contrast.json`, ni el código. Así, cuando F1 consuma tokens desde el CSS de componentes, los falsos positivos desaparecen sin mantenimiento manual.
