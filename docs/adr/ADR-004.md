# ADR-004: Separación IA (ai-core / ai-providers / knowledge) + contrato de grounding

- **Estado**: Aceptado (SPEC v3)
- **Fecha**: 2026-08

## Contexto

El AI Assistant debe responder basándose exclusivamente en la documentación del DS, con el LLM desacoplado del proveedor (primera implementación: NVIDIA Build — gratuito, OpenAI-compatible; modelo `deepseek-ai/deepseek-v4-flash-0731` como configuración, validado con llamada real — ver nota de actualización) y del retrieval.

## Decisión

Paquetes con dependencias en una sola dirección (actualizado a la
implementación real tras F6/F7):

```
ai-core ──► knowledge
  ▲            ▲
  │            │
ai-providers  react/metadata
(implementa   (alimenta el
 AIProvider)   corpus)
```

- **ai-core**: contratos (`AIProvider`, `ChatMessage`, `AIResponse`, `AIAnswer`)
  - `buildGroundedMessages` (PromptBuilder) + **orquestación** `answerQuestion`
    (query → retrieval → gate → context → prompt → provider → `AIAnswer`). Sin
    HTTP, sin SDKs, sin proveedores concretos. Única dependencia runtime:
    `knowledge`.
- **ai-providers**: `NvidiaProvider` (NVIDIA Build) y `MockProvider`
  (tests/CI/offline). La app nunca los importa; el provider lo elige `apps/api`
  por env.
- **knowledge**: corpus + `Retriever` determinista + `buildContext` sobre la
  metadata pública (`@ods-ai/react/metadata`, JSON). Sustituible por un
  `EmbeddingRetriever` futuro sin tocar nada más.

**Contrato de grounding (reglas duras):**

1. El LLM puede **sintetizar** (explicar, resumir, comparar, recomendar, combinar) información recuperada, pero **nunca introducir hechos no respaldados** por el contexto.
2. **El LLM nunca genera código nuevo.** Cualquier código mostrado procede verbatim de los ejemplos recuperados/canónicos (`*.examples.tsx`).
3. **Citas exclusivamente del retrieval**: el LLM no decide fuentes; la UI pinta los `referencedComponents` del `AIAnswer` (garantía programática, F6.1).
4. Sin fuentes relevantes → el gate no llama al LLM (respuesta determinista de "no cubierto").

**Retrieval (ajuste real):**

- El gate pasa cuando **al menos un resultado alcanza `minScore`**, y **solo las fuentes que alcanzan `minScore` se inyectan en el contexto**.
- `minScore`/`topK`/pesos son **configurables** (`AskOptions`). **Defaults reales**: `minScore = 20`, `topK = 3`, `temperature = 0.2`, sobre la **escala absoluta** del retriever (name=100 · name-contains=60 · tag=30 · variant=25 · prop=20 · token=10 · description/a11y=5 · example=3). La afinación se validó con la suite de evaluación determinista (F5.1: Top-1/Top-3 100%, 0 falsos positivos; `packages/knowledge/src/eval/`).

## Alternativas consideradas

- Un solo `packages/ai` con LLM + retrieval: acopla lo que debe cambiar por separado.
- Retrieval server-side en `apps/api`: duplicaría el índice y forzaría al backend a conocer el modelo de documentación. Se **descartó para `apps/api`**: la orquestación vive en `ai-core` (server-side), y `apps/api` es una capa HTTP fina que no conoce knowledge. El retrieval server-side convierte el grounding en **garantía de producto** (la API key nunca llega al navegador; el contexto lo construye el servidor).

## Consecuencias

- Cambiar de proveedor = cambiar config en `apps/api`; cambiar de retrieval = nueva implementación de `Retriever`.
- La API key vive solo en server (`apps/api`).
- El contrato de grounding (reglas 1–4) se mantiene intacto y se verifica por
  tests (F6.1): `referencedComponents` deriva solo del retrieval (garantía
  programática, no por prompt); el contexto enviado al provider ===
  `buildContext()`; sin contexto relevante el provider no se llama.

## Actualizaciones (2026-08)

**F6** — `ai-core` asume la **orquestación** del flujo grounded
(`answerQuestion`), añadiendo la dependencia runtime `ai-core → knowledge` que
el ADR original no contemplaba ("ports, sin dependencias"). Se mantiene el
contrato de grounding (reglas 1–4) y la dirección única: **knowledge no conoce
IA**. Flujo en `docs/ai-core.md`.

**Reconciliación de SPEC (tras F6.1/F7.1)** — el retrieval pasa a ser
**server-side** (en `ai-core`, no en el navegador como decía el ADR original):
la UI futura consumirá `apps/api` por HTTP (`POST /api/ask`, ver ADR-005). Los
defaults del gate se actualizan a `minScore 20` / `topK 3` (escala absoluta).
